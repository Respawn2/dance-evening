# Ресурсы и операции REST API

Перечень составлен до описания OpenAPI и до кода: по нему в ЛР 4Б пишется
контракт. Коды ответов взяты из критериев приёмки. Единый формат ошибки —
RFC 9457; подробно описывается в ЛР 4Б.

| Требование | Ресурс | Операция | Коды ответов | Роль |
| --- | --- | --- | --- | --- |
| `FR-01`, `FR-14` | `evenings` | `GET /v1/evenings?category=` | 200 | открыт |
| `FR-02` | `evenings/{id}` | `GET` | 200, 404 | открыт |
| `FR-06` | `evenings/{id}/attendance` | `GET` — состав «Кто идёт» с ролями и счётчиками | 200, 404 | открыт |
| `FR-03` | `evenings` | `POST` | 201, 422, 409 (пересечение вечеров организатора) | organizer |
| `FR-22` | `evenings/{id}/cancellation` | `POST` с причиной | 201, 409 (вечер начался), 404 (чужой вечер), 422 (без причины) | organizer |
| `FR-04` | `evenings/{id}/registrations` | `POST` с ролью в паре | 201, 409 (лимит; уже записан; вечер начался), 422, 404 | visitor |

## Решения

**Отмена и снятие — один обработчик или два?** В модели предметной области
это разные события с разными правами (`RegistrationCancelled`
и `RegistrationWithdrawn`, расхождение Р-1). Но ресурс один — факт прекращения
записи; различие в том, кто его создаёт и обязательна ли причина. Решение:
**один обработчик** `POST /v1/registrations/{id}/cancellation`, роль
определяется маркером, причина обязательна для роли `organizer`. Довод: два
обработчика с почти одинаковым телом разойдутся при первом изменении.

**Состав — отдельный ресурс.** «Кто идёт» нужен и на странице вечера, и сам
по себе; он публичен (без маркера, решение конфликта К-2) и кешируется
отдельно от страницы (`ADR-0005`). Решение: `GET /v1/evenings/{id}/attendance`
возвращает состав; страница вечера включает его же.

**Цена роли — без отдельной операции.** `FR-07` вычисляется из политики цен
и текущего баланса при каждом чтении (`AC-07.5`), поэтому текущая цена входит
в ответ `GET /v1/evenings/{id}`; отдельного эндпоинта нет — иначе цена
и состав смогли бы разойтись.

**Уведомления — не REST-операции.** `FR-10` и `FR-11` — асинхронные события:
доставка через брокер и обработчик (ЛР 6А), REST-эндпоинтов для них нет.

**Ресурсы — существительные.** Действия вне CRUD выражены подресурсами:
`/cancellation`, `/confirmation`, `/arrival`, `/no-show` — создание фактов,
а не вызовы процедур.
