# 4. Подписанный маркер доступа со сроком жизни 15 минут

- **Статус**: принято
- **Дата**: 2026-11-07
- **Участники**: вся команда (1 человек)

## Контекст

`NFR-02` требует маркер на действия с записями, вечерами и отзывами; просмотр
публичен (решение конфликта К-2). Нужно выбрать способ проверки подлинности
и управления правами. Способ выбирается здесь, реализация — в ЛР 4Б вместе
с контрактом API: выбор менять дорого, реализация — обычная работа.

## Движущие факторы

- `NFR-02`: срок жизни маркера — не более 15 минут; посетитель отменяет
  только свою запись; список на входе, снятие и отмена вечера — только
  организатор этого вечера
- `C-06`: внешние платные службы не используются — внешний поставщик проверки
  подлинности исключён
- До ЛР 6А общего хранилища состояния нет: вариант с сессиями на сервере
  потребовал бы завести его раньше, чем он нужен для своей задачи
- `NFR-05`: решение не должно добавлять службу в окружение

## Рассмотренные варианты

| Вариант | За | Против |
| --- | --- | --- |
| **Подписанный маркер (JWT)** | Без состояния: проверка без обращения к хранилищу; срок 15 минут — прямо из `NFR-02`; роль организатора — поле маркера | Отзыв до истечения срока невозможен без списка отозванных |
| Сессии на сервере | Отзыв мгновенный; идентификатор не содержит данных | Состояние на сервере; нужна общая память или sticky-сессии — до ЛР 6А её нет |
| Внешний поставщик (OAuth 2.0 / OIDC) | Пароли не хранятся у нас | Внешняя зависимость — против `C-06`; регистрация танцоров через вузовский вход бессмысленна |
| Ключ API | Проще всего | Не годится для людей: нет срока жизни и роли |

## Решение

**Подписанный маркер доступа со сроком жизни 15 минут и обновляющий маркер
со сроком 7 дней.** Права — через поле роли пользователя (`visitor` /
`organizer`); проверка владельца записи — сравнением идентификатора из
маркера с автором записи; проверка организатора вечера — сравнением
с полем `organizer_id` вечера, на сервере.

Пароли (регистрация своя, `C-06`) хранятся только как хеш функции для
паролей — Argon2id с солью; реализация — ЛР 4Б. Хеш общего назначения
не допускается: подбирается по готовым таблицам.

**Определяющий довод** — отсутствие общего хранилища состояния до ЛР 6А
при требовании `NFR-02`. Маркер без состояния даёт проверку прав без
дополнительной службы.

## Последствия

**Положительные.** Проверка не требует обращения к хранилищу. Окружение
не прирастает службой. Срок 15 минут из `NFR-02` выполняется прямо.

**Отрицательные.** **Отзыв маркера до истечения срока невозможен.** Выход
из системы на сервере ничего не отменяет: маркер действует до истечения
15 минут. Полноценный отзыв требует списка отозванных маркеров в кеше —
появится в ЛР 6А, если понадобится. Второе: данные в маркере не зашифрованы,
только подписаны — в маркер нельзя класть ничего, кроме идентификатора
и роли.

**Что пересмотрит решение.** Требование мгновенного отзыва доступа;
необходимость хранить в маркере данные, которые нельзя показывать клиенту;
появление единой системы входа в вузе.
