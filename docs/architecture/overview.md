# Обзор архитектуры

Документ для того, кто впервые открыл проект. Даёт картину целиком за десять
минут чтения и ссылается на подробности. **Не повторяет** содержание диаграмм
и записей о решениях.

## Что это за система

Система «Вечера» — единая афиша городских вечеров (танцы, стэндап, квизы)
с записью без переписки и обратной связью после. Посетитель видит все вечера
города, записывается с указанием роли в паре, видит публичный состав «Кто
идёт» и баланс ролей; организатор публикует вечера, получает список на входе
и отзывы. Задача — убрать переписку из записи (`BR-01`) и сделать состав
вечера видимым до его начала (`BR-02`), а для танцевальных вечеров —
выправлять баланс ролей ценой (`BR-03`).

Границы: афиша, запись, вход (отметки) и отзывы — до входа и после выхода.
Оплата и тарифы, вход через внешние системы, мобильное приложение, несколько
городов, инвайт на танец — вне охвата (`C-03`, `C-06`, `FR-16`–`FR-20`).
Принцип: на самом мероприятии продукта нет.

## Как достигаются требования к качеству

| Требование | Тактика | Где реализовано | Состояние |
| --- | --- | --- | --- |
| `NFR-01` 95 % ≤ 300 мс | Кеш афиши и состава; индекс по вечеру и записи; вычисление цены при чтении | `ADR-0005`; ЛР 4А, ЛР 6А | Запланировано |
| `NFR-02` Маркер на операции | Проверка подлинности и прав; защищённость по умолчанию (перечисляется открытое) | `ADR-0004`; ЛР 4Б | Решено, не реализовано |
| `NFR-03` Диагностируемость | Структурный журнал; идентификатор запроса | ЛР 3А | Решено, не реализовано |
| `NFR-04` Сохранность при перезапуске | Хранение в базе; проверка готовности | `C-02`; ЛР 4А, ЛР 7 | Запланировано |
| `NFR-05` Стоимость изменения | Разделение ответственностей; инверсия зависимостей; порог покрытия | `ADR-0003`; ЛР 3Б, конвейер | Решено, не реализовано |

Колонка «состояние» меняется по мере работ; к защите (ЛР 9Б) в ней не должно
остаться «решено, не реализовано» без причины.

**Требования без тактик**: нет. Проверено при составлении таблицы.

## Защищённость

### Принципы

| Принцип | Как применяется |
| --- | --- |
| Наименьшие права | Процесс в контейнере не от `root` (ЛР 3А). Пользователь базы без права менять схему (ЛР 4А) |
| Защищённость по умолчанию | Обработчик требует маркер, если не включён в явный перечень открытых: афиша, страница вечера, состав (ЛР 4Б) |
| Эшелонированная защита | Проверка данных в модели, ограничения в базе, проверка прав и владельца в обработчике |
| Безопасный отказ | Ошибка проверки маркера — отказ в доступе, а не пропуск |
| Минимум поверхности | Порт базы наружу не публикуется; адреса почты в ответах не возвращаются — публичен только ник |

### Модель угроз: введение

| Угроза | Как может проявиться | Защита | Состояние |
| --- | --- | --- | --- |
| Подмена личности | Запись или отзыв от имени другого посетителя | Подписанный маркер (`ADR-0004`) | ЛР 4Б |
| Искажение данных | Изменение чужой записи, публикация вечера чужим организатором | Проверка владельца записи и организатора вечера на сервере; ограничения в базе | ЛР 4А, ЛР 4Б |
| Отказ от совершённого | «Я не отменял запись»; спор о снятии | Журнал аудита: кто и когда; причина снятия обязательна (`FR-21`) | ЛР 7 |
| Разглашение | Адреса почты пользователей; чужие записи по идентификатору | Минимум полей в ответе; 404 вместо 403 на чужое (`AC-05.3`) | ЛР 4Б |
| Отказ в обслуживании | Поток записей исчерпывает лимит вечеров ботами | Ограничение частоты; предел размера тела запроса | ЛР 4Б (простейший), ЛР 7 (с кешем) |
| Повышение прав | Посетитель открывает список на входе или снимает чужие записи | Проверка роли и организатора вечера **на сервере** | ЛР 4Б |

### Что предусмотрено и где появится

Кода нет, поэтому здесь не «сделано», а «решено»: меры приняты как правила
и появятся вместе с первым кодом.

| Мера | Где появится |
| --- | --- |
| Пароли и ключи не попадают в репозиторий: `.env` исключён, в репозитории `.env.example` | ЛР 3А |
| Секреты в журнал не пишутся: записываются идентификаторы, не персональные данные (`NFR-03`) | ЛР 3А |
| Входные данные проверяются моделями `pydantic` на границе | ЛР 3А (настройки), ЛР 4Б (запросы) |
| Процесс в контейнере работает от непривилегированного пользователя | ЛР 3А |
| Порт базы наружу не публикуется | ЛР 4А |

### Что отложено и куда

| Что | Куда | Почему не сейчас |
| --- | --- | --- |
| Проверка подлинности и прав | ЛР 4Б | Нужен контракт API |
| Журнал аудита | ЛР 7 | Вместе с наблюдаемостью |
| Ограничение частоты запросов | ЛР 4Б (выдача маркера), ЛР 7 (общий счётчик в кеше) | Нужен контракт API; общий счётчик требует кеша |
| Проверка зависимостей и образа на уязвимости | ЛР 6Б | Вместе с конвейером доставки |
| Полная модель угроз | Вне охвата курса | Введения по STRIDE достаточно для объёма проекта |

## Что осознанно не сделано

| Решение не делать | Причина |
| --- | --- |
| Микросервисы | `ADR-0003`: `C-04` — независимость служб не нужна |
| Вход через внешнего поставщика (OAuth 2.0 / OpenID Connect) | `ADR-0004`: `C-06`; свои учётные записи, пароли — только хеш Argon2id, реализация в ЛР 4Б |
| Оркестрация | `C-05`: практика на Compose |
| Мягкое удаление флагом во всех таблицах | Только где нужна история: вечера и записи живут статусами, отзывы не удаляются |
| Отдельная база для чтения | `NFR-01` достигается кешем (`ADR-0005`), сложность не оправдана |
| Премодерация отзывов | Вне охвата: барьер «только от отметившихся» (`FR-09`) достаточен для проверки гипотезы |
