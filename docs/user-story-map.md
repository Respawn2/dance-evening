# Карта пользовательских историй — «Данс-вечер»

## Активности (позвоночник пути)

| Опубликовать вечер | Найти вечер | Записаться | Прийти | Управлять записью |
|---|---|---|---|---|

## Полная карта

**Активность: Опубликовать вечер** *(организатор)*
- Задача: объявить вечер городу
  - MVP · Как организатор, я хочу создать и опубликовать вечер с местом, временем, ценой и программой, чтобы танцоры его увидели
  - v1.1 · Как организатор, я хочу указать лимит мест, чтобы контролировать наполняемость
  - v1.2 · Как организатор, я хочу серию повторяющихся вечеров, чтобы не создавать каждый заново

**Активность: Найти вечер** *(танцор)*
- Задача: увидеть все вечера города
  - MVP · Как танцор, я хочу видеть единую афишу вечеров, чтобы не мониторить четыре паблика ВК
  - v1.1 · Как танцор, я хочу фильтр по стилю (бачата / сальса / меренге), чтобы не листать лишнее
  - v1.2 · Как танцор, я хочу уведомление о новом вечере, чтобы узнавать первым
- Задача: понять суть вечера
  - MVP · Как танцор, я хочу открыть страницу вечера и увидеть место, время, цену и баланс ролей, чтобы решить, идти ли

**Активность: Записаться** *(танцор)*
- Задача: занять место
  - MVP · Как танцор, я хочу записаться на вечер, указав роль (ведущий / ведомая), чтобы закрепить место без переписки
  - MVP · Как танцор, я хочу видеть текущую цену для моей роли, чтобы знать, сколько вход
  - v1.1 · Как танцор, я хочу повторить прошлую запись в один шаг
- Задача: получить подтверждение
  - MVP · Как танцор, я хочу получить подтверждение записи, чтобы быть уверенным, что меня записали

**Активность: Прийти** *(обе роли)*
- Задача: попасть в список
  - MVP · Как организатор, я хочу видеть список записавшихся, чтобы не вести его руками
  - MVP · Как организатор, я хочу отмечать пришедших, чтобы знать фактическую посещаемость
  - v1.2 · Как танцор, я хочу отметиться по QR-коду, чтобы не искать имя в списке

**Активность: Управлять записью** *(танцор)*
- Задача: отменить
  - MVP · Как танцор, я хочу отменить запись, чтобы место освободилось для других
  - v1.1 · Как танцор, я хочу перенести запись на другой вечер

## Позвоночник MVP

Организатор опубликовал вечер → танцор увидел его в афише → открыл страницу,
увидел баланс и цену → записался с ролью → получил подтверждение → организатор
видит список → танцор при необходимости отменил, место освободилось.

Минимальный сквозной путь: убери любой шаг — сценарий разваливается.
Без публикации нет вечера, без записи нет списка, без отмены места зависают.

## Критерии приёмки (истории позвоночника)

### Создать и опубликовать вечер

**Сценарий 1. Успешная публикация**
- Дано: организатор авторизован
- Когда: заполняет заведение, дату, время, базовые цены для ролей и публикует
- Тогда: вечер появляется в афише, у него постоянная ссылка

**Сценарий 2. Прошедшая дата**
- Дано: организатор указывает вчерашнюю дату
- Когда: нажимает «Опубликовать»
- Тогда: показано «Нельзя создать вечер на прошедшую дату», вечер не публикуется

### Увидеть афишу

**Сценарий 1. Есть вечера**
- Дано: в системе два анонсированных вечера
- Когда: танцор открывает афишу
- Тогда: видит оба, отсортированные по дате, ближайший сверху

**Сценарий 2. Пустой результат**
- Дано: анонсов нет
- Когда: танцор открывает афишу
- Тогда: видит «Пока нет анонсированных вечеров», страница не выглядит ошибкой

### Записаться с указанием роли

**Сценарий 1. Успешная запись**
- Дано: на вечер есть места, танцор не был записан
- Когда: нажимает «Записаться» и выбирает роль «ведомая»
- Тогда: запись создана, счётчик ведомых вырос, показано подтверждение

**Сценарий 2. Мест не осталось**
- Дано: лимит вечера 40 мест, записалось 40
- Когда: танцор пытается записаться
- Тогда: показано «Мест не осталось», запись не создаётся

**Сценарий 3. Вечер уже прошёл**
- Дано: дата вечера — вчера
- Когда: танцор открывает страницу вечера
- Тогда: кнопка записи недоступна, показано «Вечер прошёл»

### Динамическая цена для роли

**Сценарий 1. Перекос ролей**
- Дано: записалось 12 ведомых и 4 ведущих; порог перекоса — 5 человек
- Когда: ведущий открывает страницу вечера
- Тогда: видит сниженную цену для ведущих и счётчики ролей; базовая цена показана зачёркнутой

**Сценарий 2. Баланс в норме**
- Дано: записалось 7 ведомых и 5 ведущих
- Когда: танцор открывает страницу
- Тогда: обе роли видят базовую цену, счётчики ролей видны

### Список записавшихся (организатор)

**Сценарий 1. Актуальный список**
- Дано: на вечер записались 15 человек
- Когда: организатор открывает список
- Тогда: видит имена, роли и отметки о приходе, счётчики ролей сверху

**Сценарий 2. Отмена отражается**
- Дано: танцор только что отменил запись
- Когда: организатор обновляет список
- Тогда: танцора в списке нет, счётчик роли уменьшился

### Отмена своей записи

**Сценарий 1. Успешная отмена**
- Дано: у танцора активная запись на завтра
- Когда: отменяет запись
- Тогда: место освободилось, счётчики ролей и цена пересчитались

**Сценарий 2. Вечер уже начался**
- Дано: время начала вечера наступило
- Когда: танцор пытается отменить запись
- Тогда: отмена недоступна, показано «Вечер уже начался — скажите организатору на входе»

## Приоритизированный бэклог (MoSCoW)

| Приоритет | История | Обоснование |
|---|---|---|
| **Must** | Создать и опубликовать вечер | Без него нет объекта системы |
| **Must** | Единая афиша | Первое, что видит танцор; снимает боль №3 |
| **Must** | Страница вечера (место, время, цена, баланс) | Без неё решение «идти» не принимается |
| **Must** | Запись с указанием роли | Ядро; без ролей нет баланса |
| **Must** | Видимый баланс ролей | Ядро продукта, боль №1 |
| **Must** | Динамическая цена для дефицитной роли | Механизм выправления баланса, боль №1 |
| **Must** | Список записавшихся + отметка прихода | Снимает боль №2, данные для заведения |
| **Must** | Отмена записи | Иначе места зависают |
| **Should** | Подтверждение записи (уведомление) | Уверенность танцора; требует интеграции |
| **Should** | Напоминание накануне | Снижает no-show; требует интеграции |
| **Could** | Фильтр афиши по стилю | Удобство, не гипотеза |
| **Could** | Повтор записи в один шаг | Удобство для постоянных |
| **Won't** | Онлайн-оплата | Вне охвата — см. requirements.md |
| **Won't** | Цифровой инвайт, диджей, история партнёрств, мобилка | Вне охвата — см. requirements.md |
