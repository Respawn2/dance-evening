# Процесс — «Данс-вечер»

## Команда

| Участник | Зоны ответственности | Контакт |
|---|---|---|
| <ФИО> | Требования и продукт · Репозиторий и процесс · Качество · Инфраструктура | @ник |

Работаю один. По методичке один участник может держать несколько зон; все четыре
зоны покрыты. Зоны здесь — не разделение труда, а чек-лист: ни одна не должна
повиснуть. Состав зафиксирован <дата> и не меняется до конца курса.

## Подход

По методичке (раздел про выбор подхода): команда из одного человека за одним
столом — полный фреймворк не нужен, формализация создаст расходы без пользы.
Использую облегчённый процесс: непрерывный поток задач (Kanban) с недельными
контрольными точками. Спринты и церемонии не внедряю.

## Ритм

| Событие | Когда | Длительность | Формат |
|---|---|---|---|
| Фикс-час | раз в неделю | 30–60 мин | Сверка с ганттом, обновление бэклога, запись в журнал, план недели |
| Ретроспектива | раз в две недели, внутри фикс-часа | 15 мин | Что работало / что мешало / одно изменение процесса |

## Принятие решений

- Все решения по продукту и архитектуре фиксируются письменно (с модуля 07 —
  в формате архитектурного решения)
- Правило соло: любое сомнительное решение записывать с рассмотренной
  альтернативой и причиной, по которой отказался — иначе через месяц
  не вспомню, почему сделано именно так

## Определение готовности (DoR)

Задачу можно брать в работу, если:
- [ ] есть критерии приёмки в формате Дано — Когда — Тогда
- [ ] указано, какой истории из карты она соответствует
- [ ] понятно, каким изменением в интерфейсе или API проявится
- [ ] нет открытых вопросов к формулировке
- [ ] задача помещается в одну неделю; если нет — разбита

## Определение завершённости (DoD)

Задача считается сделанной, если:
- [ ] код влит в основную ветку через pull request
- [ ] проведено самостоятельное ревью: diff перечитан до слияния, все замечания линтера устранены
- [ ] конвейер проверок зелёный (сборка, тесты, линтер)
- [ ] написаны тесты на критерии приёмки, они проходят
- [ ] документация обновлена (README или docs/)
- [ ] добавлена запись в CHANGELOG.md
- [ ] изменение проверено на чистом окружении, а не только «у меня работает»

⚠️ Ревью второго участника недоступно — команда из одного человека. Компенсация:
саморевью с перерывом (не сливать сразу после написания), строгий линтер,
обязательный конвейер, проверка на чистом окружении. Вариант согласован
с преподавателем <дата>.

Проверка формулировки по методичке: работу должен принять человек, не
участвовавший в её обсуждении. В одиночном проекте этот человек — «я через
месяц».

## Инструменты

| Назначение | Инструмент | Требование |
|---|---|---|
| Бэклог и задачи | GitHub Projects | доступ у меня, история изменений |
| Карты (CJM, USM) | таблицы в Markdown | читается без внешних сервисов |
| Диаграммы | Mermaid в Markdown | версионируется вместе с текстом |
| Документы | Markdown в docs/ | обязательно по методичке |
