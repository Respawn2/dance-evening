# Матрица прослеживаемости

Связывает требования с решениями, моделью, кодом и проверками. Обновляется
**в том же запросе на слияние**, в котором меняется требование, решение или
тест. Полнота матрицы проверяется на защите (ЛР 9Б).

**Состояния**: `Записано` → `Спроектировано` → `Реализовано` → `Проверено`

Колонки «Код» и «Проверка» заполняются по мере реализации (первые заполнены в ЛР 3): код — по мере реализации,
проверки — в ЛР 4Б и 5. Колонка «Источник» называет сторону или происхождение
требования и контекст предметной области (ЛР 2Б).

## Обратная проверка: шаг пути пользователя без требования

| Шаг пути (ЛР 1А) | Из какого требования следует |
| --- | --- |
| Увидела вечер в афише | `FR-01` |
| Открыла страницу вечера | `FR-02` |
| Оценила состав | `FR-06` (у нетанцевальных — без ролей, формулировка покрывает) |
| Записалась | `FR-04` |
| Получила напоминание | **Требования не было** → добавлено `FR-11` (Should): путь предусматривал напоминание, в списке историй MVP его не было; шаг покрывается выпуском после MVP, помечено |
| Пришла и отметилась | `FR-08` — отметку делает организатор в списке на входе; отдельного требования для посетителя не потребовалось |
| Оставила отзыв | `FR-09` |
| Сценарий «отмена» | `FR-05` |

Находки обратной проверки: одна — шаг «получила напоминание» остался без
требования и закрыт `FR-11`. Организаторский путь (публикация → список →
итоги) покрыт `FR-03`, `FR-08`, `FR-09` без пропусков.
