# Журнал изменений

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [0.5.0] — 2026-11-07

Лабораторная работа 3, часть 3Б — модуль 08: предметная область в коде,
доведённая рефакторингом до агрегатов ЛР 2Б. Поведение не изменилось.

### Добавлено

- Сценарий создания записи `RegistrationService` — по агрегатам и правилам
  из ЛР 2Б, без знания о HTTP и SQL
- Слой предметной области `src/evenings/domain/`: агрегаты `Evening`
  и `Registration` с инвариантами, правила сценария чистыми функциями,
  ошибки без кодов HTTP
- Порты рядом с потребителем: два хранилища, часы, порождение
  идентификаторов, оповещение (метод назван по событию)
- Реализации: хранилища в памяти, системные часы, журнальное оповещение;
  заготовка `PostgresRegistrationRepository` под ЛР 4А
- Стратегия правил записи по категориям вечера (`services/policies.py`):
  у танцевальных роль в паре обязательна, у остальных запрещена (`AC-04.5`)
- Корень композиции `api/dependencies.py` — фабрика, единственное место
  выбора реализаций
- 26 тестов предметной логики без HTTP: правила по отдельности, сценарий
  на дублях (подставки, шпион, поддельные реализации)
- `docs/refactoring-notes.md`: точка отсчёта, аудит тестируемости, запахи,
  преобразования, швы, три паттерна, «было и стало» с числами
- Конвейер: шаг «Граница слоёв» в задании «Код» (по `ADR-0003`), задание
  «Единый язык» — имена глоссария в коде и запрещённые слова

### Изменено

- Обработчик записи сведён к преобразованию HTTP ↔ сценарий; тело запроса
  проверяет `pydantic`, ошибки — таблицей кодов
- `tests/conftest.py`: фикстура `_fresh_storage` сбрасывает кеш корня
  композиции — набор тестов не зависит от порядка
- Глоссарий: колонка «в коде» в проверке «на три совпадения»; термины
  следующих работ помечены
- `docs/traceability.md`: колонки «код» и «проверка» для `FR-04`, `FR-10`,
  `NFR-03`, `NFR-05`

### Удалено

- Глобальные словари `_EVENINGS` и `_REGISTRATIONS` из обработчика
- Отправка письма `smtplib` из обработчика и домысливание адреса
  (`f"{user_id}@example.com"`)

## [0.4.0] — 2026-11-07

Лабораторная работа 3, часть 3А — модуль 07: первый сервис.

### Добавлено

- Сервис серверной части на FastAPI: `GET /health` (живость, без обращений
  к внешним системам) и `GET /version`
- Настройки из переменных окружения с проверкой на старте (`pydantic-settings`):
  `DATABASE_URL` обязательна и без значения по умолчанию, опечатка в `.env`
  не проходит молча; сервис не стартует при неполной настройке
- Структурный журнал: JSON вне разработки, идентификатор запроса
  в заголовке `X-Request-Id`, пришедший извне переиспользуется
- Образ контейнера: зависимости до кода, непривилегированный пользователь,
  версия подставляется при сборке; окружение из двух служб в `compose.yaml`
  (сервис и PostgreSQL 17, том, ожидание готовности базы, порт базы наружу
  не публикуется)
- Тесты настроек и обработчиков: AAA, табличные с `ids`, включая
  отрицательные случаи; фикстура изолирует тесты от машины
- Конвейер: задания «Код: формат, типы, тесты» (uv + ruff + mypy + pytest
  с порогом покрытия 70 %) и «Образ контейнера» (сборка и ответ `/health`)
- `NFR-06` определение версии работающего кода — найдено обратной проверкой
  от кода (шаг 15 ЛР 3А)
- `uv.lock` в репозитории; `.python-version` (3.13); `.env.example`;
  `.dockerignore`; хуки pre-commit (ruff, ruff-format)

### Изменено

- `README.md`: разделы «Как запустить» и «Конфигурация»
- `docs/pipeline.md`: таблица проверок выросла до восьми заданий, исключения
  ruff (`RUF001–RUF003`, `N818`) с причинами
- `docs/requirements.md`: `NFR-06`; доля обязательного пересчитана — 12 из 28

## [0.3.0] — 2026-11-07

Лабораторная работа 2 «Проектирование системы» — модули 03–06, без кода.

### Добавлено

- `docs/requirements.md` переписан под требования с идентификаторами:
  6 заинтересованных сторон, 3 бизнес-требования, 22 функциональных
  требования с критериями приёмки в форме «дано — когда — тогда»
  (включая граничные случаи), 5 требований к качеству с числами и
  обоснованиями, 6 ограничений, приоритизация MoSCoW (доля обязательного
  44 %), 4 конфликта требований, 3 предположения, раздел об использовании
  AI-инструментов
- `docs/traceability.md` — матрица прослеживаемости на 20 требований
  (`Must` и `Should`) с контекстами, критерии без проверок, обратная
  проверка пути пользователя (нашла шаг «напоминание» — добавлен `FR-11`)
- `docs/domain/` — модель предметной области (ЛР 2Б): расшифровка сессии
  моделирования событий (19 событий, 5 расхождений в словах, 4 вопроса без
  ответа), карта контекстов `context-map.mmd` (основной «Вечера и записи»,
  поддерживающие «Отзывы и репутация» и «Учёт участников», узел уведомлений
  общего назначения), 4 агрегата с 16 инвариантами и событиями, глоссарий
  из 16 терминов с именами в коде
- `docs/adr/` — журнал из 5 записей (MADR): правила ведения, Python 3.13
  и FastAPI, модульный монолит с гексагональным устройством, подписанный
  маркер на 15 минут, кеш афиши и состава на 5 секунд (решение конфликта
  К-1); указатель и форма `docs/templates/adr.md`
- `docs/architecture/overview.md` — обзор: границы, таблица решений, тактики
  для всех требований к качеству, защищённость по замыслу с введением
  в модель угроз STRIDE, перечень осознанно не сделанного
- `docs/architecture/` — диаграммы (ЛР 2Г): контекст C4, контейнеры C4
  с пометками работ, последовательность записи на вечер с ветвями отказов,
  модель данных (4 сущности); README с читателями диаграмм, соглашением
  об оформлении и результатом пяти сверок
- `docs/api/resources.md` — 14 ресурсов и операций REST с кодами ответов
  и ролями; решения: один обработчик для отмены и снятия, состав — отдельный
  публичный ресурс, уведомления — не REST
- `FR-21` снятие записи организатором и `FR-22` отмена вечера — найдены
  сессией моделирования (расхождение Р-1), требования не было
- Конвейер: задание «Записи о решениях» (обязательные разделы MADR,
  указатель), задание «Диаграммы» (отрисовка всех `.mmd`), в
  `scripts/check_docs.py` — строки матрицы без идентификатора и разделы NFR
  без величины с единицей
- `docs/process.md`: раздел «Использование AI-инструментов» — итоги
  упражнений всех четырёх частей

### Изменено

- Порядок модулей 03–08 приведён к программе курса: проектирование
  (03–06) идёт до кода, каркас (07–08) — после. Обновлены `docs/gantt.md`
  (даты и контрольные точки: «Сервис поднимается» — конец М07) и
  `docs/roadmap.md` (вехи R1 «Проект» и R2 «Каркас» поменялись местами)
- Слово «отмена» разделено на три термина: отмена записи, снятие записи,
  отмена вечера; «роль» — на роль пользователя и роль в паре
- `README.md`: раздел «Документы» начинается с обзора архитектуры,
  добавлены матрица, журнал решений, диаграммы и ресурсы API
- `docs/pipeline.md`: таблица проверок выросла до пяти заданий, локальный
  запуск — с mermaid-cli, обновлена настройка защиты main
- Плейсхолдер «порог уточнить у студий» из требований работы 1 закрыт
  числом 3:1 с пометкой «допущение» (`BR-03`, `П-3`)
